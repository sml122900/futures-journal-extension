## 세션 — Emergency Brake 상태 기반 트리거 대응

---

## 배경

서버가 6개 사용자 정의 트리거로 재설계됨. 상태 기반 트리거(#1 총 포지션, #2~3 시간 차단, #4 손실 한도, #5 간격)는 진입 클릭 시점이 아닌 "현재 상태"를 주기적으로 확인해야 함. 크롬 확장도 이에 맞게 업데이트.

---

## 변경 내용

### 1. banner.js (신규)

`src/content/banner.js`:
- 차단 상태일 때 페이지 상단에 fixed 빨간 띠 표시
- `Banner.show(reasons)` / `Banner.hide()` / `Banner.update(reasons)` / `Banner.clear()`
- 닫기 버튼: sessionStorage에 dismissed_at 저장 → 5분 후 자동 재표시
- 복수 차단 시: "3가지 차단 조건 활성 — (이유1 | 이유2 ...)" 형식

### 2. content.js 수정

- init()에서 `_checkAndUpdateBanner()` 초기 호출
- `setInterval(_checkAndUpdateBanner, 5 * 60_000)` 5분 폴링
- `chrome.runtime.onMessage` 리스너: background에서 `BLOCKING_STATUS_UPDATE` 수신 시 배너 갱신
- `_checkAndUpdateBanner()`: `ApiClient.fetchBlockingStatus()` 호출 → 차단 시 배너 표시, 해제 시 배너 clear

### 3. api-client.js 수정

- `fetchBlockingStatus()` 추가: `GET /api/extension/blocking-status` 호출

### 4. background.js 수정

- `blockingStatus` 알람 생성 (1분 후 시작, 5분 주기)
- `keepWarm` 알람 리스너를 통합 핸들러로 재구성
- `blockingStatus` 알람 발동 시:
  - `/api/extension/blocking-status` fetch
  - 활성 비트겟 탭(`www.bitget.com/futures/*`)에 `BLOCKING_STATUS_UPDATE` 메시지 전달

---

## 작동 흐름

```
[페이지 로드]
  → content.js init()
  → _checkAndUpdateBanner() 즉시 호출
  → 차단 상태면 Banner.show(reasons)

[5분마다]
  → content.js: _checkAndUpdateBanner() 폴링
  → background.js: blockingStatus 알람 → 탭에 메시지
  → content.js: BLOCKING_STATUS_UPDATE 수신 → 배너 갱신
```

## 주의사항

- `banner.js`는 manifest.json의 content_scripts에 등록해야 함 (다음 배포 시 확인)
- 상태 기반 트리거 #1(총 포지션), #4(손실 한도)는 서버에서 포지션 목록 없이 체크하면 정확도 낮음 — 현재는 빈 배열로 전달 (향후 포지션 캐시 연동 필요)
